# UI Patterns

## Core UI Philosophy

The interface should feel:

* focused
* operational
* modern
* lightweight
* visual-first
* productivity-oriented

The UI should emphasize:

* clarity
* momentum
* visibility
* progress
* alignment

Every screen should feel:

* intentional
* breathable
* interactive
* alive

Avoid:

* static-looking dashboards
* excessive table layouts
* dense admin panels
* enterprise software patterns

---

# Layout Philosophy

## Preferred Layout Structure

Use:

* sidebar navigation
* sticky topbar
* content-first pages
* modular dashboard sections
* card-based composition

The interface should rely heavily on:

* spacing
* hierarchy
* grouping
* visual rhythm

Avoid:

* overcrowded pages
* deeply nested layouts
* full-width dense tables
* multi-sidebar layouts

---

# Page Composition Rules

Each page should contain:

1. Clear page title
2. Small contextual subtitle
3. Primary action button
4. Summary metrics
5. Main interactive content
6. Supporting insights/activity

The user should immediately know:

* where they are
* what matters
* what action to take

---

# Dashboard Patterns

Dashboards should feel:

* dynamic
* operational
* informative
* glanceable

Prefer:

* metric cards
* progress rings
* lightweight charts
* activity timelines
* momentum widgets
* status indicators

Avoid:

* giant analytics grids
* spreadsheet-style layouts
* overwhelming data density

---

# Navigation Patterns

## Sidebar Navigation

Sidebar should be:

* minimal
* icon-supported
* collapsible
* cleanly grouped

Suggested sections:

* Mission Control
* Objectives
* Mission Syncs
* Team Momentum
* Insights
* Workspace Settings

Avoid:

* long navigation trees
* nested dropdown menus
* more than 2 hierarchy levels

---

# Card Patterns

Cards are the primary UI structure.

Cards should:

* feel lightweight
* use subtle elevation
* contain clear hierarchy
* have strong spacing

Preferred card content:

* title
* status
* progress
* contextual action
* supporting metadata

Avoid:

* overly bordered cards
* cluttered card layouts
* excessive text

---

# Progress Visualization Patterns

Progress should be visible everywhere.

Use:

* circular progress rings
* segmented progress bars
* trend arrows
* completion indicators
* animated counters

The UI should constantly reinforce:

* momentum
* completion
* alignment
* mission health

Avoid:

* plain percentage text without visuals

---

# Form Patterns

Forms should feel:

* guided
* lightweight
* intelligent

Prefer:

* step-based flows
* grouped sections
* inline validation
* progressive disclosure

Avoid:

* giant enterprise forms
* overwhelming field dumps
* long vertical forms

Use:

* sliders
* segmented selectors
* smart defaults
* contextual hints

---

# Table Usage Rules

Tables should be:

* secondary
* simplified
* visually enhanced

If tables are used:

* keep rows spacious
* include avatars/icons
* add progress indicators
* include quick actions

Avoid:

* raw spreadsheet-style grids
* dense data-heavy rows
* excessive columns

Prefer cards over tables whenever possible.

---

# Modal & Drawer Patterns

Prefer:

* slideovers
* side panels
* inline editing

Avoid:

* excessive popup modals
* disruptive confirmation dialogs

Modals should only be used for:

* focused decisions
* destructive actions
* compact workflows

---

# Motion Patterns

Motion should feel:

* premium
* subtle
* purposeful

Use:

* fade transitions
* hover elevation
* animated progress
* panel transitions
* loading skeletons

Avoid:

* excessive bounce
* flashy animation overload
* distracting transitions

Animations should support:

* clarity
* momentum
* responsiveness

---

# Empty State Patterns

Empty states should:

* feel optimistic
* guide action
* maintain visual polish

Include:

* concise messaging
* visual illustration/icon
* single primary CTA

Good:

* “No active missions yet.”
* “Create your first objective to begin tracking momentum.”

Avoid:

* “No data available.”

---

# Status Indicator Patterns

Statuses should be:

* visually lightweight
* color-assisted
* easy to scan

Use:

* pills
* badges
* dots
* subtle labels

Avoid:

* overly saturated colors
* giant alert banners everywhere

---

# AI Insight UI Patterns

AI-generated insights should feel:

* embedded
* subtle
* premium

Avoid:

* chatbot-first UX
* giant AI branding
* overwhelming AI sections

Prefer:

* insight cards
* smart summaries
* contextual recommendations
* subtle intelligence indicators

The AI should feel:

* assistive
* ambient
* operational

---

# Mobile Responsiveness Rules

The app must remain:

* visually premium
* usable
* fast

On mobile:

* stack cards vertically
* collapse sidebar
* prioritize key actions
* reduce dashboard density

Avoid:

* shrinking desktop UI directly
* overcrowded mobile layouts

---

# Typography Rules

Typography should drive hierarchy.

Prefer:

* strong headings
* muted secondary text
* generous spacing
* concise labels

Avoid:

* tiny fonts
* excessive capitalization
* dense paragraph blocks

The UI should feel:

* readable
* calm
* modern

---

# Component Consistency Rules

Components should:

* behave consistently
* reuse patterns
* maintain spacing rhythm

Avoid:

* random component variations
* inconsistent padding
* different interaction styles

The product should feel:

* cohesive
* system-driven
* intentionally designed

---

# Final UI Goal

Every screen should feel like:

* a modern productivity tool
* a premium SaaS dashboard
* an operational command center

NOT:

* an HR portal
* an ERP system
* an admin template
* a CRUD application
