# Naming Conventions

## Product Language Philosophy

The platform should NOT use traditional HRMS terminology everywhere.

Avoid language that feels:

* corporate
* bureaucratic
* robotic
* appraisal-heavy
* compliance-driven

The product should sound:

* modern
* motivating
* collaborative
* momentum-focused
* productivity-oriented

Tone:

* concise
* intelligent
* human
* startup-like
* action-oriented

---

# Naming Style Rules

## UI Labels

Prefer:

* short labels
* clear action words
* emotionally positive wording

Good:

* Create Mission
* Sync Progress
* Review Alignment
* Update Momentum

Avoid:

* Submit Employee Goal Form
* Quarterly Review Submission
* Performance Management Portal

---

# Button Naming

Buttons should feel:

* active
* lightweight
* modern

Prefer:

* Continue
* Save Draft
* Publish
* Sync Update
* Approve Mission
* Resolve Alert

Avoid:

* Execute
* Submit Request
* Finalize Workflow
* Process Approval

---

# Dashboard Widget Naming

Widgets should sound:

* intelligent
* operational
* visual

Good examples:

* Team Momentum
* Mission Health
* Alignment Pulse
* Progress Snapshot
* Upcoming Syncs
* At-Risk Objectives
* Completion Velocity
* Focus Areas

Avoid:

* KPI Table
* Employee Goal Metrics
* Workflow Analytics

---

# AI Feature Naming

AI features should sound:

* subtle
* premium
* helpful

Avoid:

* “AI Assistant”
* “Chatbot”
* “GPT Feature”

Prefer:

* Insight Engine
* Momentum Insights
* Smart Summary
* Risk Signals
* Focus Suggestions
* Alignment Intelligence

---

# Status Naming

Avoid boring status labels.

## Instead of:

* Pending
* Approved
* Rejected

Use:

* Awaiting Review
* Aligned
* Needs Revision

---

## Instead of:

* Not Started
* In Progress
* Completed

Use:

* Ready to Start
* On Track
* Achieved

---

# Notification Copy Style

Notifications should feel:

* concise
* calm
* modern

Good:

* “Your mission was aligned successfully.”
* “2 objectives may require attention.”
* “Quarterly sync window opens tomorrow.”

Avoid:

* “Your request has been processed.”
* “Submission completed successfully.”
* “Approval workflow initiated.”

---

# Empty State Copy

Empty states should feel:

* motivating
* optimistic
* lightweight

Good:

* “No active missions yet.”
* “Start by creating your first objective.”
* “Your team momentum will appear here.”

Avoid:

* “No records found.”
* “Database empty.”
* “Nothing to display.”

---

# Design System Naming

Component naming should remain:

* clean
* predictable
* scalable

Prefer:

* mission-card
* progress-ring
* sync-panel
* insight-widget
* momentum-chart

Avoid:

* random abbreviations
* unclear internal names
* generic component naming

---

# Code Naming Rules

## Variables

Prefer:

* readable
* semantic
* human-friendly

Good:

* missionProgress
* teamMomentum
* syncStatus
* alignmentScore

Avoid:

* data1
* tempState
* missionObjFinal

---

# Folder Naming

Prefer:

* lowercase
* kebab-case
* feature-based organization

Example:

* /mission-control
* /mission-sync
* /team-momentum
* /alignment-review

Avoid:

* deeply nested folder structures
* unclear naming
* generic “utils2” style naming

---

# Final Product Personality

The entire product should sound like:

* a modern execution platform
* a collaborative productivity tool
* a mission-driven workspace

NOT:

* legacy HR software
* compliance tooling
* enterprise bureaucracy software
